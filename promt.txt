Build a complete Python Telegram automation system with two Telegram bots:

1. A private control bot owned by the user.
2. A Telegram automation client that communicates with another Telegram bot through the normal Telegram user/client API.

IMPORTANT SECURITY REQUIREMENT:
Do NOT implement credential harvesting, password searching, leaked-account searching, "login:password" collection, credential stuffing, authentication bypass, or processing of stolen credentials. The system must only process non-sensitive files/data that the user is authorized to access.

GOAL

The user should be able to control the automation entirely from their own Telegram bot.

Example workflow:

1. The user opens the control bot.
2. The user sends a command such as:

/add example1.com
/add example2.com
/add example3.com

3. The system adds the URLs to a queue.
4. A worker processes the queue sequentially.
5. For each URL, the automation client sends a predefined search/request command to the authorized target bot.
6. The target bot may respond with a confirmation/question and then provide a TXT file or another authorized result file.
7. The worker downloads the returned file.
8. The control bot sends the resulting file back to the user.
9. The worker continues automatically with the next URL.
10. The user can monitor status and control the queue at any time.

QUEUE

Use a persistent queue so that restarting the application does not lose pending URLs.

Each queue item should contain:

- unique ID
- URL
- status
- creation timestamp
- start timestamp
- completion timestamp
- retry count
- result file path
- error message, if any

Possible states:

PENDING
PROCESSING
WAITING_FOR_RESPONSE
WAITING_FOR_FILE
COMPLETED
FAILED
CANCELLED

PROCESSING LOGIC

Process only one URL at a time.

Pseudo-flow:

FOR each URL in queue:

mark item as PROCESSING

send the authorized search/request command
wait for the target bot response

if target bot asks the user to select an available result type:
    select only the authorized, non-sensitive option

wait for the resulting file

validate the file

download the file

send the file through the control bot

mark item as COMPLETED

continue with next queue item

The system must never process arbitrary Telegram messages as commands without validating their origin and conversation state.

TELEGRAM CLIENT

Use an appropriate Telegram client library such as Telethon.

The client should:

- log in using the user's own authorized Telegram account
- identify the target bot by username
- send requests to that bot
- monitor replies
- recognize the expected response
- recognize file/document messages
- download authorized result files
- associate each file with the correct queue item

Do not automate interactions with Telegram accounts or bots in a way that bypasses Telegram restrictions.

If a timeout occurs:

- log the problem
- retry according to configuration
- after the maximum retry count, mark the item FAILED
- continue with the next queue item

"./results/"
