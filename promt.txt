You are an expert Python/AI engineer. Modify/build the project so it becomes a complete Virtual AI system for Termux on Android.

1. Main objective

Create a web-based Virtual AI that combines 5 independent real AI models hosted by Groq into one intelligent virtual model.

Each AI model must use a different Groq API key:

- "GROQ_API_KEY_1"
- "GROQ_API_KEY_2"
- "GROQ_API_KEY_3"
- "GROQ_API_KEY_4"
- "GROQ_API_KEY_5"

The application must run locally on Termux and expose the web interface at:

"http://127.0.0.1:22200"

Do not create fake/mock AI models. Every model must make a real API request to Groq.

Give each model a different specialization.

For example:

Model 1 — Reasoning Agent

Responsible for:

- deep reasoning
- decomposition of problems
- identifying assumptions
- finding logical solutions

Model 2 — Research Agent

Responsible for:

- gathering information
- analyzing external information
- identifying useful facts
- using browser tools when necessary

Model 3 — Critical Agent

Responsible for:

- challenging the other agents
- detecting errors
- identifying hallucinations
- checking contradictions
- proposing corrections

Model 4 — Engineering Agent

Responsible for:

- technical solutions
- programming
- architecture
- implementation details
- debugging

Model 5 — Strategic Agent

Responsible for:

- comparing the proposed solutions
- selecting the strongest approach
- optimizing the final result
- making the final recommendation

The roles must be configurable in the code.

5. Parallel execution

The five Groq models should preferably process the user's request in parallel, not sequentially.

Use asynchronous Python where appropriate.

For example:

USER QUESTION
      │
      ├──► MODEL 1
      ├──► MODEL 2
      ├──► MODEL 3
      ├──► MODEL 4
      └──► MODEL 5
               │
               ▼
        COLLECT RESPONSES
               │
               ▼
           SYNTHESIS

Do not make the user wait unnecessarily for model 1 to finish before model 2 starts.

Implement:

- timeouts
- exception handling
- retries where appropriate
- graceful handling of one failed API key
- rate-limit handling

If one model fails, the remaining models should still be able to produce an answer.

6. Synthesis layer

The Virtual AI must combine the five responses.

Do not simply concatenate the responses.

Create a synthesis stage that receives:

Original user request

+
Model 1 response

+
Model 2 response

+
Model 3 response

+
Model 4 response

+
Model 5 response

The synthesis agent should:

1. Compare the responses.
2. Identify agreements.
3. Identify contradictions.
4. Detect weak reasoning.
5. Prefer well-supported conclusions.
6. Use useful information from each model.
7. Produce one coherent final answer.
8. Avoid mentioning internal implementation unless appropriate.
9. Never blindly trust one model.

The final response displayed to the user should feel like it came from one Virtual AI, not five separate chatbots.
